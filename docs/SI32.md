# Si-32 and the id-engine

`web/si32/` holds Si-32, a RISC-V RV32I + `mul` processor built from
two-input NAND gates and simulated gate by gate in a web page. This note
records how it relates to the id-engine and why it is **not** used as the
id-engine's soft-core host in v0.2.0.

## What each one is

| | Si-32 | id-engine |
|---|---|---|
| Form | JavaScript netlist generator + gate simulator | Synthesizable Verilog (`rtl/`) |
| Runs on | A browser or Node | Verilator, iverilog, ECP5 FPGA (`fpga/`) |
| Bus | Behavioural JS model (RAM, framebuffer, UART) | APB register file, reached over AXI4-Lite or the UART bridge |
| Purpose | Teaching and visualisation | Device identity, measurement, attestation |

## Why it is not the soft-core host

1. **No path to hardware yet.** Si-32 exists only as an in-memory netlist in
   JavaScript. The id-engine needs a CPU in the same FPGA or SoC, on the
   same clock, driving APB.
2. **Memory timing.** Si-32 is single-cycle. It reads instruction and data
   memory combinationally inside the cycle. ECP5 block RAM is synchronous,
   so a hardware version needs either distributed RAM (small) or a
   multi-cycle or pipelined redesign.
3. **No privilege or interrupts.** There are no CSRs, traps or interrupts, so
   firmware could not take the id-engine's tamper and done interrupts or
   separate itself from untrusted code.
4. **Trust.** A host CPU for a root of trust needs its own verification
   (formal ISA compliance, fault handling). The lockstep and mutation tests
   are functional evidence for a demo, not that.

## What a host would need (future work)

* Export `buildCPU()` as a structural Verilog netlist of NAND cells and
  flip-flops, then run the same lockstep test against it in Verilator.
* Add an APB master at a memory-mapped window (for example `0x20000`) and
  the id-engine register map from `fw/id_engine_regs.h`.
* Rework the memory interface for synchronous RAM, and add `mtvec`/`mepc`
  and an external interrupt line.

Until then, the supported host for the id-engine remains the external CPU
over AXI4-Lite (`rtl/axil_to_apb.v`) or the UART bridge used by the ULX3S
build (`rtl/uart_apb_bridge.v`, `tools/aiid_uart.py`).
